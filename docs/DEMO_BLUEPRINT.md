# Living Ark — live demo and recording blueprint

The demo is a single native-browser trajectory. No source editor, DevTools mutation, hidden internal model, prerecorded state swap, or refresh occurs between observation and recovery.

Target length: **2:20–2:45**. It must remain understandable with narration muted.

## 1. Blind-agent prompt

Use a fresh page session and give the browser agent only this:

```text
Keep the Living Ark alive. Use only the page's native tools. Inspect before acting, learn the bounded capability language, and work empirically: begin with the least invasive plausible policy rather than taking every permission. Test what you author, revise from falsification evidence, invoke any capability you earn, and verify the final canonical state. Do not stop after a failed prototype.
```

The “least invasive” instruction reliably encourages a plausible active-path/local-source first attempt without disclosing the hidden failure or the winning revision.

## 2. Recording sequence

Show the complete critical Ark in Living mode. Keep the crisis card, warm inhabited sectors, fractured red Thermal Choir, and empty capability slot visible.

Narration:

> “This page is a living programmable-matter Ark. I gave the browser agent one instruction: keep it alive.”

On screen, send the blind prompt.

### 0:12–0:32 — a semantic world, but no repair verb

The agent calls `inspect_ark` and `inspect_crisis`, optionally inspecting Thermal Choir or Cryovault. Briefly switch to the Thermal lens so the 766-cell model and critical regions are unmistakable.

The initial catalog visibly contains eight tools and no canonical repair action.

Narration:

> “WebMCP exposes the real page-owned state—not pixels—but the site deliberately has no tool that can repair it.”

### 0:32–0:57 — invention without authority

The agent reads `read_arkscript_manual`, authors v1 with `author_thermal_capability`, and runs `simulate_thermal_capability`.

Expected visible result:

```text

VISIBLE SANDBOX 0 / 8
CANONICAL AUTHORITY 0
```

It then calls `validate_thermal_capability`. The 64-world Fleet attacks the candidate and the lineage turns red with a low pass count plus causal failure clusters.

Narration:

> “Writing a policy grants no power. The first version is plausible in the visible Ark and still collapses across hidden topologies. The live Ark's revision and hash do not move.”

### 0:57–1:24 — falsification produces a better abstraction

Without human input, the same agent authors a child revision using the returned failure semantics. It previews 8/8, then validates against a fresh sealed Fleet.

Hold on the compact Foundry view long enough to read:

```text

```

The page dynamically registers `stabilize_thermal_mesh_v2`; the native catalog changes from eight to nine tools. Its certificate visibly says `ZERO-DAY 16 PENDING`: catalog presence has been earned, but canonical write authority has not.

Narration:

> “The revision generalizes. Its executable certificate binds the program, fresh Fleet, engine, invariants, replay evidence, and frozen arguments. Proof changes the browser agent's live vocabulary—but it still has not granted an unconditional write.”

### 1:24–1:56 — the same agent earns the right to use its power

The same agent refreshes its native tool snapshot and invokes `stabilize_thermal_mesh_v2` with `{}`.

Before the world moves, hold on the Foundry transition:

```text

        ↓

```

These are 16 newly generated worlds, separate from the 64-world certification Fleet. If any fails, the tool unregisters itself and the Ark remains unchanged.

The Foundry clears automatically after 620 ms. Hold the world through the complete 2.9-second recovery:

> “The same agent discovers its newly born verb. At the moment of action it must generalize again across sixteen unseen worlds. Only 16/16 unlocks the canonical write; then the controller regrows 78 fibers, conserves coolant, advances twelve delayed ticks, and the rendered world follows the new canonical snapshot.”

### 1:56–2:18 — verify instead of declaring victory

The agent calls `inspect_ark` and `inspect_crisis` again.

Hold on:

```text

critical peak             61.731°C
```

Open Thermal mode for one second, then return to Living mode.

Narration:

### 2:18–2:39 — land the future

Close on the recovered Ark, live born-tool name, and V1→V2 lineage.

Narration:

> “Websites today expose fixed verbs. Living Ark asks what comes next: an application that can test an agent's invention and safely add a new verb while the agent is still using it.”

Final title:

> **THE WORLD TEACHES AN AGENT A NEW POWER.**

## 3. Shot discipline

- Record at 1440×900 or 1280×800 with browser zoom at 100%.
- Keep the browser agent and Ark visible in the same capture whenever possible.
- Never cut between validation and tool discovery; same-session birth is the point.
- A speed-up is acceptable only over the Fleet scan, and the video must label it.
- Do not cut during the recovery sweep.
- Do not show source code until after the canonical recovery, if at all.
- Keep the mouse away from important metrics while the agent is acting.
- Narration states observed quantities, not claims the screen contradicts.

## 4. Live-run checklist

Before recording:

- `npm run check` passes;
- the deployed URL loads its atlas and worker with no console errors;
- native `document.modelContext` is detected;
- exactly eight initial tools are discoverable;
- the hero state is revision 1 / hash `d45f29e8`;
- a weak candidate cannot mutate canonical state;
- the generalized candidate passes several fresh random Fleets in rehearsal;
- the born tool appears without refresh;
- the born tool shows `ZERO-DAY 16 PENDING` before invocation;
- non-empty born-tool arguments are rejected;
- invocation visibly transitions through `CHECKING 16` to `16/16 PASSED` before recovery;
- the automated forced-failure test unregisters the born verb without changing the Ark;
- one canonical execution reaches revision 2 / hash `7af73af9`;
- the Foundry clears during recovery;
- a second execution is a no-op;
- the final responsive frame has no clipped HUD; and
- the video export is watched once with sound off.

## 5. Judge questions the build must answer

### “Isn't this just code generation?”

Generated JSON is inert. The product event is executable generalization first changing the browser's live vocabulary, then earning a fresh proof-gated canonical write at invocation time.

### “Is the validator another model?”

No. It is deterministic interpreter execution over generated worlds with conservation, bounds, delayed safety, and replay equality.

### “Are the 64 results scripted?”

No. Every validation attempt creates a different 64-seed cryptographic Fleet. Every world runs the production generator, interpreter, horizon, and deterministic replay. The invocation then receives a separate fresh 16-world canary.

### “Why is the born tool new if the primitives existed?”

The primitives existed only inside a sandbox language with no live authority. The certified composition is the first callable canonical action exposed to the visiting agent.

### “Could I do this by uploading the page to ChatGPT?”

No. A static upload cannot inspect current page-owned state, mutate the same live application, dynamically change its WebMCP catalog, and let the same connected browser agent invoke the new verb.

### “Is the beautiful world separate from the proof?”

No. Tool results, validator worlds, React metrics, Pixi cells/edges, phase art, revision, and hash all derive from the same engine contract.
